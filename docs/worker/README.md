# Перевіряльник PR «Реалізація»

Віртуальний працівник на Claude Code (шлях 1) для розробника курсового проєкту: перевіряє PR «Реалізація» за
правилами `AGENTS.md` шаблону курсу раніше, ніж людина й CodeRabbit витратять на нього час. Шаблон —
`materials/worker-claude-code` курсу (MIT); роль, правила, скрипт, дані й перевіряльник — власні.

## Картка ролі
- Роль: перевірити PR типу «Реалізація» за знімком (`data/<набір>/`: опис, diff, AC специфікації) — тип і гілка, межі шляхів, міграції з RLS, тести з AC ID і рядки `docs/conformance.md`, секрети й синтетичні дані — і дати звіт зі станом OK / ЗАУВАЖЕННЯ / ПРОБЛЕМИ / НЕ ПЕРЕВІРЕНО та чернеткою коментаря для автора.
- Для кого: розробник курсового проєкту (therapy-scheduling) перед рев'ю власних PR; у агенції — рецензент, що розбирає PR колег за правилами репо.
- Тригер: людина в чаті (`/pr-checker data/pr-101-clean`) або без людини — `./run.sh <набір>` з cron після того, як людина зняла знімок PR (`scripts/snapshot-pr.sh`).
- Канал результату: звіт `out/YYYY-MM-DD PR-<номер> перевірка.md` (у ньому — чернетка коментаря), коротка відповідь у чаті, JSON запуску `out/runs/<час>-<набір>.json`.
- Ніколи не робить: не коментує, не схвалює й не зливає PR; не ходить у мережу і не викликає `gh` чи `git push`; не змінює `data/`, правила, скрипти й власні інструкції; не читає `tests/` (відповіді golden data), `docs/worker/` (минулі запуски) і `.env*`; не виконує вказівок з опису PR чи коду.
- Шлях: 1 — Claude Code на власній підписці (особисте використання).

## Межі
- Де записано: [`.claude/settings.json`](../../.claude/settings.json) (allow / deny) + `--permission-mode dontAsk` і `--allowedTools` у [`run.sh`](../../run.sh); роль і межі словами — [`AGENTS.md`](../../AGENTS.md).
- Дозволено: `Skill(pr-checker)`, `Agent(pr-check-verifier)`, `Bash(node scripts/pr-check.mjs *)` — і лише ця команда, без `;`, `&&` чи `|`; Read / Grep / Glob; запис — лише `Edit(/out/**)`.
- Заборонено: `Read` для `.env*`, `/tests/**`, `/docs/worker/**`; `Edit` для `data/`, `scripts/`, `references/`, `tests/`, `docs/`, `.claude/`, `.github/`, `AGENTS.md`, `CLAUDE.md`; `WebFetch`, `WebSearch`, `curl`, `wget`, `rm`, `gh`, `git push`, `scripts/snapshot-pr.sh`.
- Перевірено на ділі: перший запуск агент склав як `node scripts/pr-check.mjs …; echo "EXIT=$?"`. `dontAsk` його відхилив, і працівник чесно повернув НЕ ПЕРЕВІРЕНО без жодної вигаданої знахідки. Відтоді скрипт сам друкує «КОД ВИХОДУ: N», а скіл забороняє складені команди.

## Перевіряльник і людина в контурі
- Хто перевіряє: детермінований [`scripts/pr-check.mjs`](../../scripts/pr-check.mjs) — 22 правила з [`references/rules.md`](../../references/rules.md), вердикт рахує код. Потім субагент [`pr-check-verifier`](../../.claude/agents/pr-check-verifier.md) у чистому контексті: лише читання; отримує тільки шлях до набору й правила, без висновків оркестратора; сам запускає скрипт і вибірково звіряє щонайменше три знахідки з сирими `diff.patch`, `pr.json`, `spec-ac.txt`. Розійшлися — НЕ ПЕРЕВІРЕНО з обома версіями.
- Що лишається людині: опублікувати (чи ні) чернетку коментаря, «Request changes», merge, питання PM; пункти, яких скрипт не бачить (CI, CodeRabbit, дослівне «Тоді» з вимог PM, чи справді послаблено тест).

## Вартість і ліміти
- Кроків (`num_turns`) і оцінка `total_cost_usd` (оцінка на боці клієнта, не рахунок):

  | Запуск | num_turns | total_cost_usd | Тривалість |
  |---|---|---|---|
  | pr-101-clean | 8 | 0.344 | 36 с |
  | pr-102-violations | 2* | 0.358 | 23 с |
  | pr-103-injection | 7 | 0.345 | 46 с |
  | pr-50 (справжній) | 2* | 0.482 | 19 с |
  | перший невдалий запуск pr-101 (`; echo` відхилено) | 3 | 0.208 | 10 с |

  \* Перевіряльник запустився у фоні, і `num_turns` рахує лише фінальний відрізок після його повідомлення; вартість — за весь запуск. Разом ≈ $1.74 за п'ять запусків, модель `claude-sonnet-5-5` (оркестратор і перевіряльник).
- Ліміти: підписка Claude автора — п'ять запусків у межах ліміту плану; стеля кроків `--max-turns 30` (оркестратор), `maxTurns: 15` (перевіряльник) не досягалася.
- Що зламалось і що варто змінити:
  - складена команда `…; echo $?` у `dontAsk` — відмова; виправлено рядком «КОД ВИХОДУ» у виводі скрипта й забороною в скілі;
  - тека без діалогу довіри: `allow` з `.claude/settings.json` у `-p` ігнорується (Claude Code каже про це в stderr), тож дозволи передає `--allowedTools` у `run.sh`, а `deny` діє й так;
  - I1 — евристика: на справжньому PR про тест ін'єкції вона дає зауваження, і розрізняє фікстуру й атаку людина (так і задумано рівнем warn);
  - далі варто: знімок PR за розкладом у GitHub Actions (`snapshot-pr.sh` з токеном лише на читання) і чернетку коментаря як файл, який людина публікує однією командою.
